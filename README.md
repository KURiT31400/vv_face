# 顔認証 写真仕分け Streamlit アプリ

`ref/` の参照画像をもとに `image/` の写真を顔認証し、`output/<人物名>/` へ自動で仕分けする Streamlit アプリです。
複数人が写った写真は、顔ごとに候補を確認しながら手動で確定できます。

顔認識エンジンは [InsightFace](https://github.com/deepinsight/insightface)（buffalo_l / CPU 実行）を使用しています。

## 2つのアプリ

用途に応じて 2 つのエントリポイントがあります。

| ファイル | 想定 | 対象写真の指定 | 出力 |
|---|---|---|---|
| `face_app_pub.py` | **公開版**（Streamlit Community Cloud など） | ブラウザからアップロード | ZIP ダウンロード |
| `face_app.py` | ローカル実行 | PC 上のフォルダパスを指定 | PC 上のフォルダへ直接出力 |

公開版はサーバー上で動くため、利用者の PC のフォルダを直接読み書きできません。
そのため写真はアップロード、結果は ZIP ダウンロードという形になります。

## 動作環境

- Python 3.9 以上
- macOS / Windows / Linux（GPU 不要）


## フォルダ構成

```
.
├── face_app_pub.py     # 公開版（アップロード → ZIP）
├── seasons.json        # シーズン名 → 参照フォルダ の対応表
├── requirements.txt
├── packages.txt        # Streamlit Cloud 用（OpenCV が必要とする OS パッケージ）
├── .streamlit/
│   └── config.toml     # アップロード上限などの設定
├── README.md
├── ref/                # 参照画像
│   ├── MF05_山田太郎.jpg    # 選手：ポジション+背番号_氏名
│   ├── GK01_鈴木一郎.jpg
│   └── staff/              # スタッフ（任意）
│       ├── 監督_佐藤次郎.jpg      # 役職_氏名
│       ├── フィジカルコーチ_田中三郎.jpg
│       └── 通訳_高橋四郎.jpg
├── image/              # 【ローカル版のみ】仕分け対象の写真
└── output/             # 【ローカル版のみ】自動生成（人物名フォルダ）
```

`image/` と `output/` は `.gitignore` で除外しています。リポジトリに含めるのは `ref/` だけです。

### 参照画像の置き方

| 形式 | 例 | 人物名になるもの |
|---|---|---|
| 1人1ファイル | `ref/MF05_山田太郎.jpg` | ファイル名（拡張子なし） |
| 1人1フォルダ | `ref/MF05_山田太郎/01.jpg, 02.jpg …` | フォルダ名 |
| スタッフ | `ref/staff/コーチ_田中三郎.jpg` | ファイル名（拡張子なし） |
| その他の関係者 | `ref/etc/MC_鈴木五郎.jpg` | ファイル名（拡張子なし） |

同一人物の参照画像が複数あるほど精度が上がります。

**選手**は `ポジション+背番号_氏名` にしておくと、人物一覧でポジション別・背番号順に並びます。
認識する接頭辞と表示順は次のとおりです。

`GK` → `DF` → `MF` → `FF` → `FW` → `監督` → `SP`（マスコットなど） → `staff` → `etc` → `その他`

一覧にない接頭辞は「その他」にまとめられます。増やしたい場合はコード先頭の `POS_ORDER` に追記してください。

**スタッフ**は `ref/staff/`（または `ref/スタッフ/`）に `役職_氏名.jpg` の形式で入れてください。
中の画像が1人ずつ別人として登録され、人物一覧では次のように整理されます。

同じ形式のフォルダとして `ref/etc/` も使えます（MC・来賓など、staff とは分けたい関係者向け）。

- `監督_◯◯.jpg` → **監督** グループ（監督だけを独立表示）
- それ以外の役職 → **staff** / **etc** グループにまとめて表示（役職順 → 氏名順）
- サムネイル表示では写真の下に **役職** と **氏名** が2行で表示されます

`staff` フォルダが無い場合は何も変わりません（従来どおり動作します）。

### 対象フォルダの選び方（ローカル版）

サイドバーの **フォルダ設定 → 対象フォルダ** の「変更」ボタンで選択画面が開きます。
選び方は3通りあり、どれでも構いません。

1. **「🖥 PC のフォルダ選択画面を開く」** — macOS / Windows の見慣れたフォルダ選択ダイアログが開きます
2. **アプリ内のフォルダ一覧** — サブフォルダのボタンをクリックして移動し、「✅ この場所に決定」。
   各フォルダの画像枚数が表示されるので、目的のフォルダを見つけやすくなっています
3. **パスを直接入力** — Finder からフォルダを入力欄へドラッグ＆ドロップすると
   パスが入ります（`file://` 形式や引用符つきのパスも自動で解釈します）

> ブラウザの仕様上、フォルダを画面へドロップしても**パスは取得できません**。
> 1 か 2 の方法をお使いください（3 の入力欄へのドラッグは有効です）。

**出力先は自動で決まります。** 対象フォルダと同じ階層に `output/` を作成し、その下に
人物名フォルダを作ります（例: 対象が `.../20260812/` なら出力は `.../output/`）。
無ければ自動作成されるので、設定は不要です。

### 参照画像を後から追加する

**「👥 人物一覧」タブ →「➕ 参照画像を追加する」** からブラウザ経由で追加できます。
ファイル名（拡張子を除いた部分）がそのまま人物名になるので、選手は `MF05_山田太郎.jpg`、
スタッフは `コーチ_田中三郎.jpg` のように付けてください。保存先は「選手など / スタッフ」で選べます。

同じ人物名を追加すると上書きされます。参照フォルダは `ref/` に固定です。

**参照画像の登録は自動です。** 初回の解析時にまとめて顔ベクトルを作り、以降はキャッシュされます。
参照画像を追加・差し替えるとフォルダの内容が変わったことを検知して、次の解析時に自動で登録し直します。
手動で「登録」ボタンを押す必要はありません。



## シーズンの追加（公開版）

公開版の「シーズン」選択肢は `seasons.json` で管理します。**表示名 → 参照フォルダ名** を書くだけです。

```json
{
  "2026/27 SEASON": "ref",
  "2027/28 SEASON": "ref_2027_28"
}
```

新シーズンを追加する手順:

1. 新しい参照画像フォルダ（例 `ref_2027_28/`）を `face_app_pub.py` と同じ階層に置く
2. `seasons.json` に 1 行追加する
3. コミットして push する（Streamlit Cloud なら自動で再デプロイされます）

先頭に書いたものが初期選択になります。`seasons.json` が無い場合は `ref/` を
「2026/27 SEASON」として扱い、`ref_*` フォルダがあれば自動で選択肢に加えます。

## 使い方

解析と出力は分離されています。**解析しただけでは写真は仕分けされません。**

### 公開版（`face_app_pub.py`）

1. サイドバーで **シーズン** を選ぶ
2. **① 写真を追加** — 仕分けしたい写真をアップロード（最大 200 枚）
3. **② 解析** — 各写真の顔と候補人物を記録
4. **③ レビュー** — 複数人が写った写真の割り当てを確定
5. **④ 出力** — ZIP をダウンロード（人物名フォルダごとに格納）／判定結果の CSV も取得可

### ローカル版（`face_app.py`）

1. サイドバーで **対象フォルダ** を選ぶ
2. **① 解析** — 「未解析を解析」を押すだけ（**参照画像の登録は自動**）
3. **② レビュー** — 写真ごとに割り当てを確定
4. **③ 出力** — 対象フォルダと同じ階層の `output/<人物名>/` へ出力。ドライランで件数だけ先に確認できる
5. **④ 結果** — 人物ごとの枚数・判定一覧を確認、CSV 出力

### レビュー対象の絞り込み

②レビューの上部で、どの写真を確認するかを選べます。

| 対象 | 内容 |
|---|---|
| **複数人の写真**（既定） | 顔が2つ以上検出された写真 |
| **すべての写真** | 全部。**1人だけの写真の誤判定を直したいときはこれ** |
| **要確認（該当なし・低確度）** | 誰にも該当しなかった写真と、類似度がしきい値ぎりぎりの写真 |
| **未確認のみ** | まだレビュー画面で開いていない写真。**取りこぼし防止に使う** |

顔認証は誤判定することがあります。おかしい写真を見つけたら「すべての写真」に切り替えて、
その写真を選んで選択し直してください。手動で確定した内容は自動判定より常に優先されます。

### 観客席など、顔が多すぎる写真

スタンドが写り込んだ写真では、観客の顔が数十個検出されます。全部を照合すると時間がかかるうえ、
結果もほぼ役に立ちません。そこで検出された顔が **「1枚あたりの最大顔数」（既定 20）** を超えた場合は、
**大きく写っている 3 人だけを照合**し、残りは無視します。判定一覧では「観客席（一部）」と表示されます。

**手前の被写体は必ず含まれます。** 大きい順に選ぶため、観客の前でプレーしている選手のように
「顔が最も大きく写っている人」が取りこぼされることはありません。

観客だけを撮った写真では、選ばれた 3 人も誰にも該当しないため `その他/` に入ります。
また、120 人写っていても 3 人分の計算で済むので、解析時間も大きく短縮されます。

集合写真をきちんと照合したい場合は上限を 30〜40 に上げてください。0 で無制限になります。

### 一覧にない人・該当なしの写真

選択肢の最後に **「その他（一覧にない人）」** があります。これを選ぶと `その他/` フォルダに
仕分けされます。参照画像に登録していない人（相手選手、来賓、家族など）をまとめる用途に使えます。

誰にも該当しなかった写真も、同じ `その他/` に入ります（サイドバーの
「該当なしの写真も その他/ に入れる」が既定でオン。オフにすると出力されません）。

**候補が絞れなかった場合は、レビュー画面の初期値も自動的に「その他」になります。**
誰かに割り当て直したいときだけ選び直してください。
なお、小さすぎる顔（最小顔サイズ未満）は最初からチェックが外れています。

### 人物の指定（レビュー画面）

写真の右側は、上から順に **背番号の検出結果 → 名前で追加する → 仕分け先 → 検出された顔ごとの指定** です。
確定内容（仕分け先）を先に確認でき、直したいときだけ下の顔を操作する流れになっています。

**名前で追加する**

背中向きなどで顔が検出されなかった人を、名前で選びます。
背番号が読み取れた場合は初期値として入ります。

**仕分け先**

いまの選択でどのフォルダに入るかが表示されます。下の顔の操作は即座にここへ反映されます。

**検出された顔ごとの指定**

検出された顔のサムネイルの下に、**自動認識した人物名とチェック欄**、その下にプルダウンがあります。

- **確度が高い顔は自動でチェックが入ります**。違うときだけ外す／選び直してください
- **人物が違うとき**はプルダウンで選び直します。候補は `MF05 山口蛍　(0.523)` のように
  類似度つきで上位に並び、その下に全メンバーが続きます。チェックのラベルも選び直した名前に変わります
- 候補が絞れなかった顔は「その他」と表示されます
- 顔の下には `顔1 / 152px / ボケ度 523` のように大きさとくっきり具合が出ます

**変更は自動保存されます。** チェックやプルダウンを触ったあと、別の写真へ移動すれば
（「次へ →」でもプルダウンで別の写真を選んでも）その内容が保存されます。
「確定して次へ」を押し忘れても失われません。

「確定して次へ」は保存して次の写真へ進むボタン、「自動判定のまま確定」は自動判定をそのまま採用、
「確定を取り消す」で自動判定に戻ります。

> レビューしていない写真は**自動判定の結果でそのまま出力されます**。
> レビューは、自動判定を直したい写真だけ行えば十分です。
> 何も変えずに次の写真へ移った場合は「未確定」のままです（自動判定と同じ内容なので保存しません）。

### ボケた顔を無視する

前景の被写体だけを見て、**背景でボケている顔は最初から無視**します。

判定は **その写真で最も鮮明な顔に対する比率** で行います。サイドバーの
**「ボケ顔とみなす比率」**（既定 15%）より不鮮明な顔は、人物照合にも
「1枚あたりの最大顔数」の数え上げにも使いません。

絶対値ではなく比率にしているのは、**くっきり具合の絶対値が写真ごとに大きく変わる**ためです。
実測すると、前景の選手 523 に対し背景の観客席は 44 前後（約 8%）でした。
別の写真では前景が 277 のこともあり、絶対値では線を引けませんが、比率なら安定して分けられます。

背景が大きくボケている写真では、これだけで観客の顔がほぼ除外されます。
ただし**被写界深度が深い写真では観客もそれなりに鮮明**で、ボケ度では分けきれません。
その場合は上の「大きく写っている3人だけ照合する」仕組みが働きます。

- **比率を上げる**（25% など）と、ややボケた人物も無視します
- **比率を下げる**（5% など）と、背景の人物まで拾い始めます
- **0** にすると比率での除外を行いません

必要なら「ボケ顔を除外（絶対値）」も併用できます。レビュー画面の各顔の下に
`顔1 / 152px / ボケ度 523` のように実測値が出るので、それを見て決めてください。
絶対値のほうは解析後に変更しても再解析は不要です（比率は再解析が必要）。

### サポーター（観客）を無視する

観客席やサイドラインの人が選手として認識されるのを防ぎます（サイドバー「サポーターの除外」、既定でON）。
**解析後に変更しても再解析は不要**で、「③ 出力」「④ 結果」にすぐ反映されます。

- **主役との比較**: その写真で一番大きい顔（主役）に比べて、**大きさも鮮明度も**一定の比率に
  満たない顔を無視します（既定: 大きさ 60% 未満 かつ 鮮明度 50% 未満）。
  どちらか一方だけなら残るので、遠くの選手やブレた選手は巻き込まれません。
  集合写真のように全員が同程度に写っている場合は、誰も除外されません。
- **小さい顔は厳しく**: 80px 未満の顔は、しきい値に +0.10 を上乗せします。
- **曖昧な顔は採用しない**: 1位と2位の類似度の差が 0.05 未満の顔は、誰とも言い切れないので採用しません。

除外された顔は、レビュー画面で「（サポーターとみなして対象外）」と表示されます。
取りこぼしが出るときは、比率を下げる（または 0）か、上乗せ・差を小さくしてください。

### 連写をシーンとして扱う

撮影時刻（EXIF）から連写のまとまり（シーン）を見つけて、仕分けに使えます
（サイドバー「シーン（連写）」→「連写シーンの扱い」）。画像の見た目は使わず、撮影間隔だけで決めます。
再解析は不要です。

**シーンの見つけ方**（既定値）

1. 撮影間隔が 1.0 秒以下の写真をつなぐ
2. つないだ中に、0.5 秒以下の間隔（連写）が 2 つ以上（＝3枚以上）あればシーン
3. 連写が 1 つだけ（2枚）の短いまとまりは、3 秒以内に別のシーンがあれば合流

手で 1 枚ずつ撮った写真（間隔が 1〜3 秒）は、つながってもシーンにはなりません。

**扱い方**

| 選択 | 動き |
|---|---|
| 使わない | シーンを使いません |
| 未判定の写真だけ補完 | 顔で判定できなかった写真に、同じシーンの人物を引き継ぎます。シーン内で 2 枚以上に判定された人物が **1 人に絞れるシーンだけ**が対象です（複数人が食い違うシーンは補完しません） |
| シーン内の全写真に人物を広げる | シーン内の全写真を、そのシーンの人物（2 枚以上に判定された人）のフォルダにも入れます |
| シーンごとのフォルダにまとめる | 人物ではなく `シーン01`、`シーン02`… のフォルダ**だけ**に入れます（人物フォルダには入れません）。人物が選ばれていれば `シーン01-MF22翁長聖` のように人名が付きます（下記）。シーンに入らなかった写真は、これまでどおり人物ごとに仕分けられます |

- 「未判定の写真だけ補完」「全写真に人物を広げる」では、レビューで**人物を選んで確定**した写真は
  変更されません。人物なしのまま「確定して次へ」「自動判定のまま確定」を押しただけの写真は、
  未確定と同じ扱いで補完の対象のままです。
- **シーンフォルダの名前**: そのシーンの人物が選ばれていれば、`シーン01-MF22翁長聖` のように
  人名を付けます。人物がいなければ `シーン01` のままです。
  - 人物とみなすのは、シーン内の **2枚以上**（設定で変更可）に顔や背番号で判定された人、
    またはレビューで**手動選択**した人（1枚でも対象）です。
  - 2〜3人いるときは `シーン03-MF22翁長聖・DF17高畑奎汰` のように「・」でつなぎます。
    **4人以上**（集合写真など）は人名を付けず `シーン03` のままです。
  - 解析やレビューが進むとフォルダ名が変わることがあります。出力し直すときは
    「出力前に人物フォルダを削除する」を使うと、前回の名前のフォルダが残りません。
- 「シーンごとのフォルダにまとめる」では、シーンに入った写真は、人物を選んで確定した写真も含めて
  シーンフォルダだけに入ります。人物フォルダに入れたい写真は、レビューで「シーンに入れない」を選んでください。
- 連写として検出されなかった写真は、レビュー画面の「**シーン（連写）への振り分け**」で
  手動でシーンに入れられます（`シーン02（DSC_0736.JPG 〜 DSC_0741.JPG・6枚）` のように範囲つきで選択）。
  「シーンに入れない」を選ぶと、その写真だけシーン処理の対象外になります。
  この選択は人物の指定より優先され、状態ファイルに保存されます。
- レビュー画面には、その写真が属するシーン番号が表示されます。
- 「④ 結果」の表に「シーン」列と、シーン処理で変わった写真の注記が出ます。
- シーン番号は、対象フォルダ内の全写真の撮影時刻から決まるので、解析の進み具合に関係なく安定しています。

### 背番号での判定（背中向きの選手）

背中を向けた選手は顔認証が効きません。そこで **ユニフォームの背番号を OCR で読み取り**、
参照画像の `ポジション+背番号_氏名` と突き合わせて人物を特定します。

- **顔で誰も判定できなかった写真にだけ**適用されます（顔認証の結果を上書きしません）
- 読み取った番号は、レビュー画面に「🔢 背番号を検出: **5番**（信頼度 1.00） → MF05 山口蛍」と表示され、
  「名前で追加する」の初期値にも入ります
- 判定一覧には「背番号」列が追加されます

**看板や観客席の数字を誤検出しないための2条件**が入っています。

1. **最小の大きさ（画像高さ比、既定 5%）** — 背番号は 6〜8%、看板やスタンドの数字は 3〜4% と
   明確に差があります。遠くの選手まで拾いたい場合は下げてください（誤検出は増えます）
2. **登録メンバーに存在する番号のみ** — 名簿にない番号は無視します

**読み取りは2つの解像度で行い、結果を統合します。** 背番号が大きく写りすぎていると
原寸では「41」が「4」に割れて読まれることがあり（実際に発生しました）、縮小すると正しく読めます。
逆に小さい背番号は原寸のほうが読めます。同じ位置から読めた数字が重なった場合は、
**桁数の多いほうを採用**するので、「41」を「4」と取り違えることはありません。

実測では、背中向きの選手が写った 6 枚すべてで背番号を正しく人物に対応づけられ、
観客席の写真では誤検出ゼロでした。処理は 0.3〜0.5 秒/枚です。

> **限界** — ユニフォームのシワ、体の角度、他の選手との重なりで読めないことがあります
> （実測では 1 枚あたり 2〜3 人中 2 人程度）。読めなかった選手はレビュー画面で
> 「名前で追加する」から手動で追加してください。
> 背番号を持たない監督・スタッフ・MC はこの機能の対象外です。

### 修正した顔を覚える（追加学習）

証明写真だけでは、**横顔・斜め後ろ・見上げた顔**は判定できません。
レビューで人物を選び直すと、**その顔を本人の参照データとして覚え、次回以降の照合に使います。**

例: `0DSC_1013.JPG` の斜め後ろの顔が「その他」になっていたので「コーチ 三好毅典」に修正
→ その角度の顔ベクトルが記録され、以後、同じような角度の写真でも三好コーチとして判定されます。

**覚えるのは「修正した顔」だけです。**

| 操作 | 学習 |
|---|---|
| 自動判定が正しく、そのままにした | **しない**（新しい情報がないため） |
| 自動判定を別の人に選び直した | **する** |
| 「その他」だった顔に人物を指定した | **する** |
| 「その他」のままにした／チェックを外した | **しない** |

自動判定の結果を覚えないので、**誤判定が自己強化されることはありません**。
サイドバーの「修正した顔を覚える」で無効にもできます。

**学習データは対象フォルダをまたいで引き継がれ、積算されます。**
保存先が `ref/.learned.npz`（参照画像と同じ固定フォルダ）だからです。
別の試合の写真を仕分けるときも、それまでに覚えた顔がそのまま使われ、新しい修正が追加されていきます。

| ファイル | 場所 | 範囲 |
|---|---|---|
| `.learned.npz`（学習データ） | `ref/` 固定 | **全フォルダ共通・積算** |
| `.face_sorting.json`（作業状態） | 各対象フォルダ | そのフォルダのみ |

1件あたり約2KBです。
**「👥 人物一覧」タブ**に人物ごとの件数が表示され、元になった写真の一覧をCSVで確認できます。
おかしな学習をしてしまった場合は、そこから**すべて削除**できます。

> **反映は次の解析からです。** 解析済みの写真の候補は記録済みのため変わりません。
> 効果を確かめるには、追加の写真を解析するか、「解析結果をすべて破棄」してやり直してください。

### 作業状態は自動保存されます

解析結果とレビュー内容は、**対象フォルダの `.face_sorting.json`** に自動保存されます。
アプリを閉じても、次に同じフォルダを開けば**続きから作業できます**。顔認証をやり直す必要はありません。

- 解析のたび／レビューで内容を変えるたび／出力のたびに保存されます
- 対象フォルダを切り替えると、そのフォルダの状態が読み込まれます
- 写真を削除した場合、その写真は読み込み時に自動で除かれます
- 最初からやり直したいときは「① 解析 → 解析結果をすべて破棄」（保存ファイルも削除されます）

212枚で約180KBの小さなファイルです。読み書きは数ミリ秒で、動作の邪魔になりません。

### 取りこぼしを防ぐ（修正済み / 確認済み / 未確認）

②レビューの上部に **解析済み / 修正済み / 確認済み / 未確認** の4つの数字が出ます。

| 表示 | 意味 | 一覧の印 |
|---|---|---|
| **修正済み** | レビューで内容を変えた写真 | ✔ |
| **確認済み** | レビュー画面で開いたが、自動判定のままにした写真 | ・ |
| **未確認** | まだ開いていない写真 | （なし） |

**「未確認」が 0 になれば全部見たことになります。** レビュー対象で **「未確認のみ」** を選び、
「確定して次へ」または「次へ →」で進めていくと、見た写真から消えていきます。

### 追加解析したあとの出力

出力タブに **「まだ出力していない写真だけ」** のチェックがあります（出力済みがある場合は既定でオン）。
50枚ずつ解析・出力していくような使い方で、前回の分を書き直さずに済みます。
**レビューで内容を変えた写真は、出力済みでも再出力されます**（仕分け先が変わっているため）。

### 分割して解析する（枚数が多い場合）

写真が多いと解析に時間がかかるため、**何回かに分けて解析できます**。結果は積み上がっていきます。

- **1回に解析する枚数**（既定 50）を指定して「未解析を解析」を押すと、その枚数だけ処理します
- 画面には **対象写真 / 解析済み / 未解析** が常に表示されます
- 途中でレビューや出力を挟んでから、「未解析を解析」で続きを再開できます
- すでに解析した写真は再解析されません。レビューで確定した内容もそのまま残ります
- 「0」を指定すると未解析をすべて処理します

解析中は **⏸ 一時停止** と **⏹ 中止** が使えます。数秒ごとに画面へ制御が戻る仕組みのため、
ボタンはすぐに反応します。一時停止は続きから再開でき、中止しても**そこまでの解析結果は保存され**、
未解析分だけを後から処理できます。

> 解析にかかる時間の大半は顔検出です。急ぐ場合はサイドバーの **検出解像度** を下げてください
> （640 → 480 など）。ただし小さく写った顔を取りこぼしやすくなります。

### レビュー画面のポイント

- 選択肢は `MF05 山田太郎　(0.523)` のように候補が類似度つきで上位に並び、その下に全メンバーが続きます
- チェックを入れた顔だけが仕分けに使われます
- 「確定」すると自動的に次の写真へ進みます。未確定の写真は自動判定の結果で出力されます
- **しきい値・最小顔サイズは解析後に変更しても再解析不要**です（③④に即反映）

## パラメータの目安

| 項目 | 説明 | 推奨 |
|---|---|---|
| 類似度しきい値 | コサイン類似度。高いほど厳格 | 0.40（誤検出が多ければ 0.45〜0.50、見逃しが多ければ 0.35） |
| 最小顔サイズ | これ未満の顔は無視 | 40px（集合写真の後方まで拾うなら 20px） |
| 検出解像度 | 大きいほど小さな顔を検出、遅い | 640（引きの写真は 1024） |
| 顔検出のしきい値 | 下げると検出しにくい顔も拾う | 0.50（横顔・マスコットを拾いたいなら 0.30） |
| 1枚あたりの最大顔数 | これを超えたら観客席とみなし照合しない | 20（0 で無制限） |
| ボケ顔とみなす比率 | 最も鮮明な顔比。これ未満は背景として無視 | 15%（0 で無効） |
| ボケ顔を除外（絶対値） | 併用したい場合のみ | 0（実測値を見て決める） |
| サポーターを無視する | 主役より小さく不鮮明な顔を無視 | ON（大きさ 60% / 鮮明度 50% / 小顔 80px で +0.10 / 差 0.05） |
| 連写シーンの扱い | 撮影間隔で連写をまとめる | 使わない（シーン専用フォルダなら「シーンごとのフォルダにまとめる」） |
| 1顔につき最上位のみ | OFF で複数候補に仕分け | ON |
| 背番号も読み取る | 背中向きの選手を背番号で判定 | ON |
| 背番号の最小の大きさ | 画像高さ比。小さい数字は看板とみなす | 5.0%（遠景も拾うなら 3.0%） |

補足:

- 初回起動時に顔認識モデル（約 300MB）をダウンロードするため、最初の解析だけ時間がかかります
- 無料枠はメモリが約 1GB です。1 回あたり 200 枚程度を目安にしてください
- ZIP が大きくなる場合は「長辺1600pxに縮小」を選ぶとサイズが 1/20 程度になります
- アップロード上限は `.streamlit/config.toml` の `maxUploadSize` で調整できます

## 注意

- 初回起動時に buffalo_l モデル（約 300MB）が `~/.insightface/models/` に自動ダウンロードされます。
- CPU 実行で 1 枚あたり 0.5〜2 秒程度です（画像サイズ・検出解像度により変動）。
- **ドライラン**にチェックを入れると、ファイルを書き込まず判定結果だけ確認できます。まず数十枚で試すことを推奨します。
- 「移動」モードでも複数人が写った写真はコピーになります（元ファイルは残ります）。
- 出力フォルダは既存があればそこに追加し、なければ自動作成します。
  **同じファイル名が既にある場合は上書きされます**（連番は付きません）。
- 顔認証は誤判定を含みます。重要な用途では必ずレビュー画面で確認してください。
- **マスコット・着ぐるみは苦手です。** 顔検出モデルは人間の顔で学習されているため、
  着ぐるみの顔は検出されないことがあります（参照画像の登録時に警告が出ます）。
  「顔検出のしきい値」を 0.30 程度まで下げると検出できる場合がありますが、
  検出できてもマスコットは表情や陰影の差が小さく、別のマスコットや人物と
  混同されやすい点にご注意ください。うまくいかない場合は参照画像から外し、
  レビュー画面で「その他」として手動で仕分けるのが確実です。

## プライバシー

顔画像は個人情報にあたります。**ご本人の同意が得られている写真のみ**をご利用ください。
取り扱いは適用される法令・所属組織の規程に従ってください。

- **ローカル版** — すべての処理が PC 上で完結し、画像が外部に送信されることはありません
  （初回のモデルダウンロードのみインターネット接続が必要です）
- **公開版** — アップロードされた写真はアプリを動かしているサーバー上の一時領域で処理され、
  セッション終了時に破棄されます。恒久的な保存や第三者への提供は行いません。
  ただし共用サーバーに一時的にアップロードされる点は利用者に明示してください
